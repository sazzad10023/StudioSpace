# StudioSpace

Single Next.js 16 (App Router) app under `src/app` on React 19.3 — a studio-rental listings front end (browse, detail, add/edit/delete listings). No tests, no CI, one package. The `README.md` is unmodified `create-next-app` boilerplate; this file is the real doc.

## External services & env

- Studio CRUD hits an external REST backend **not in this repo**, at **`http://localhost:8000`** (hardcoded in 6 files as `API_URL` / `ENDPOINT` / inline literals — no env var): `GET /get-studios`, `GET /get-studio/{id}`, `POST /add-studio`, `PATCH /update-studio/{id}`, `DELETE /delete-studio/{id}`. Records use Mongo-style `_id`. Pages will error without the backend running; if you change the URL, change it in all 6 places.
- Auth is **better-auth** (email/password + Google) over the same MongoDB (`amr_studio` db): server config in `src/lib/auth.ts`, client in `src/lib/auth-client.ts`. The `.env` (gitignored, no `.env.example`) defines `MONGODB_URL`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — auth breaks at runtime without a reachable MongoDB.

## Commands

- `npm run dev` — dev server (Turbopack + React Compiler)
- `npm run lint` — ESLint flat config (`eslint.config.mjs`); run as `npx eslint <file>` to check specific files. Beware: the strict react-hooks rules fire as **errors** on patterns already present in existing code (e.g. `react-hooks/set-state-in-effect` for `setState` inside `useEffect` bodies), so full `npm run lint` can fail on code you didn't touch — verify your work with `npx eslint <files you touched>` instead, and don't refactor others' logic just to quiet these rules.
- `npx tsc --noEmit` — typecheck (not wired into any script; run before finishing changes)
- `npm run build` — production build; `.next/` is generated output, never edit it

## Toolchain gotchas

- **React Compiler is enabled** (`reactCompiler: true` in `next.config.ts`). Do not add manual `useMemo`/`useCallback` for memoization unless profiling shows a need; write idiomatic React and let the compiler handle it.
- **Tailwind v4** — configured via the `@tailwindcss/turbopack` plugin in `next.config.ts`, not PostCSS or a `tailwind.config` file. Theme tokens/CSS variables live in `src/app/globals.css`. `@custom-variant dark` and `@theme inline` are defined there.
- **shadcn UI is `base-nova` style** (`components.json`): primitives come from `@base-ui/react`, **not Radix**, so component APIs may differ from typical shadcn examples. Concrete differences that have broken builds here: triggers take `render={<Button ... />}` instead of Radix's `asChild` (e.g. `DialogTrigger`, `AlertDialogTrigger`), and Select's `onValueChange` passes `string | null` when a value is cleared (coalesce with `?? ""`). Before building on a UI primitive, read its source in `src/components/ui/` (function-style components with `data-slot` attributes). Add new UI via `npx shadcn add <component>`.
- The `cn` helper re-exports the standalone **`cn` npm package** (`src/lib/utils.ts`), not clsx+tailwind-merge.
- **Next 16 typed route props**: pages/layouts use the generated global types (`PageProps<"/route">`, `LayoutProps<"/route">`) instead of hand-written `params`/`searchParams` types. The types live in `.next/types/` and `.next/dev/types/` (regenerated by `next dev`/`build`; both are in tsconfig `include`).
- Path alias: `@/*` → `src/*` (`tsconfig.json`).
